# Blip Builder — Monitoring Events

Documentation of all events generated by `IBlipLogger` in the Builder pipeline.

---

## Common structure (LogInput)

All events share the following root-level fields in `LogInput`:

| Field | Type | Description |
|---|---|---|
| `Title` | `string` | Event name (see tables below) |
| `EventType` | `string` | Event category: `"ActionExecution"` or `"StateExecution"` |
| `FlowVersion` | `int?` | Version of the flow being executed |
| `Channel` | `string` | Source channel domain (extracted from `message.From.Domain`) |
| `IdMessage` | `string` | ID of the message that triggered the processing |
| `From` | `string` | User identity (`userIdentity`) |
| `To` | `string` | Owner identity (`ownerIdentity`) |
| `OriginalFrom` | `string` | Original value of `message.From` |
| `OriginalTo` | `string` | Original value of `message.To` |
| `Data` | `JObject` | Event-specific fields (see each section) |

The method called on `IBlipLogger` is indicated in each event as **Logger method**.

## Flow lifecycle events (FlowManager)

### InputProcessing

Fired at the end of each incoming message processing, regardless of success or error.

| Field | Type | Description |
|---|---|---|
| `flowId` | `string` | Flow ID |
| `stateId` | `string` | Final state ID after processing |
| `input` | `string` | Serialized content of the input message |
| `inputExecutionTime` | `long` | Total execution time in milliseconds |
| `error` | `string?` | Error message, if any |
| `inputTrace` | `object?` | Full `InputTrace` object with detailed tracing |
| `traceSettings` | `object?` | Active trace settings (`TraceSettings`) |

**Logger method:** `ActionExecution`  
**EventType:** `StateExecution`  
**Paths:** success and error (always fired in `finally`)

---

### OutputProcessing

Fired after each state output evaluation (state transition).

#### Success

| Field | Type | Description |
|---|---|---|
| `flowId` | `string` | Flow ID |
| `currentStateId` | `string` | Current state ID (before transition) |
| `nextStateId` | `string?` | Next state ID (null if no output matched) |
| `outputsCount` | `int?` | Total outputs configured on the state |
| `matchedOutputOrder` | `int?` | Order of the selected output |
| `isDefaultOutput` | `bool?` | Whether the selected output is the default (no conditions) |
| `success` | `bool` | `true` |

**Logger method:** `ActionExecution`  
**EventType:** `StateExecution`

#### Error

| Field | Type | Description |
|---|---|---|
| `flowId` | `string` | Flow ID |
| `currentStateId` | `string` | Current state ID |
| `outputStateId` | `string` | Target state ID of the failed output |
| `outputOrder` | `int` | Order of the failed output |
| `isDefaultOutput` | `bool` | Whether it was the default output |
| `success` | `bool` | `false` |
| `error` | `string` | Exception stack trace |

**Logger method:** `ConversationalFlow`  
**EventType:** `StateExecution`

### InputValidation

Fired when a state has validation configured and the input **fails** validation. Not fired when there is no validation or when the input is valid.

| Field | Type | Description |
|---|---|---|
| `flowId` | `string` | Flow ID |
| `stateId` | `string` | ID of the state whose validation failed |
| `validationRule` | `string` | Rule applied: `Text`, `Number`, `Date`, `Regex`, `Type` |
| `isValid` | `bool` | `false` (event is only generated when validation fails) |
| `success` | `bool` | `true` (the validation operation itself succeeded) |

**Logger method:** `ActionExecution`  
**EventType:** `StateExecution`  
**Path:** validation failure

---

### MaxTransitionsReached

Fired immediately before throwing `FlowConstructionException` when the state transition limit per message is reached (loop detected in the flow).

| Field | Type | Description |
|---|---|---|

| `currentStateId` | `string?` | ID of the state at the moment the limit was reached |
| `transitionCount` | `int` | Number of transitions performed |
| `maxTransitions` | `int` | Configured limit (`MaxTransitionsByInput`) |
| `success` | `bool` | `false` |

**Logger method:** `ActionExecution`  
**EventType:** `StateExecution`  
**Path:** error

## Action events

All action events follow the pattern below, except for specific fields indicated in each section:

- **Logger method:** `ActionExecution`
- **EventType:** `"ActionExecution"`
- **Always present fields:** `flowId`, `actionId`, `actionTitle`, `success` (+ `error` on error path)

> `actionId` and `actionTitle` are populated from the `$id` and `$title` fields of the action's JSON definition in the flow. They are `null` when not configured.
